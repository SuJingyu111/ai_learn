# Step 025 — `softmax`：数值稳定性不是可选项

**你会做出**：`softmax`，并且它在大输入下不会变成 NaN。

**为什么是现在**：softmax 是 MNIST 网络的最后一层，Phase 04 必须有。
它也是第一个"朴素实现会真的坏掉"的算子——前面几个算子的朴素版只是慢，
softmax 的朴素版是**错**。

## 先手算

`softmax([1,2,3])` 的三个分量分别是多少？（保留 4 位小数）

然后想一下：`softmax([1000,1001,1002])` 的正确答案是什么？
朴素实现算 `exp(1000)` 会得到什么？

## 动手

1. 先写朴素版 `softmax_naive`：`exp(x_i) / Σ exp(x_j)`。
2. 跑 `[1000,1001,1002]`，亲眼看到它坏掉。
3. 再写稳定版：先减去最大值，`exp(x_i - max) / Σ exp(x_j - max)`。
   数学上完全等价（分子分母同乘 `exp(-max)`）。
4. **两个版本都留着**，测试里断言稳定版在两种输入下都对。

## 跑起来

```bash
cmake --build build-cpu --parallel && ./build-cpu/tt op-demo softmax
```

## 你应该看到

```
softmax_naive([1,2,3])          = 0.0900 0.2447 0.6652
softmax_stable([1,2,3])         = 0.0900 0.2447 0.6652

softmax_naive([1000,1001,1002]) = nan nan nan          <-- 坏了
softmax_stable([1000,1001,1002])= 0.0900 0.2447 0.6652
```

注意两个输入的**正确答案完全相同**——softmax 对输入整体平移不变。

## 卡住了

- 朴素版没出 nan 而是 `0 0 1` → 你用了 double。float32 的 `exp(1000)` 是 inf，
  `inf/inf` 是 nan。用 double 会推迟但不消除这个问题（`exp(1000)` 在 double 下
  也是 inf）。
- 稳定版结果不对 → 检查是不是只在分子减了 max，分母忘了减。

### 🎯 Additional goal — 朴素 softmax 到底在哪里炸（可选）

**假设**：float32 下 `softmax_naive` 的失效阈值就是 `exp(x)` 溢出的地方，
即 x > 88 左右（因为 float32 最大约 3.4e38，`ln(3.4e38) ≈ 88.7`）。

**做什么**：对 `[x, x+1, x+2]`，x 从 0 扫到 200，每次都跑朴素版和稳定版，
记录朴素版第一次出现 inf、第一次出现 nan、第一次与稳定版偏差超过 1e-5 的 x。

**测什么**：三个阈值 x 各是多少。再对**负方向**做一遍：
x 从 0 扫到 -200，看朴素版什么时候下溢成全 0（`0/0` = nan）。

**你可能会发现**：正向阈值确实在 88–89 附近。但**偏差超标发生得更早**——
在溢出之前，大数相除已经开始损失精度了。负方向的失效可能出现在 -87 附近
（`exp(-87)` 下溢到非规格化数或 0）。

**为什么会这样**：`exp` 把输入的加法变成输出的乘法，输入相差 1 输出就差 e 倍。
float32 的指数范围只覆盖约 ±88 的输入。减去 max 之后所有输入都 ≤ 0，
`exp` 的结果都在 (0,1] 内，永远不会溢出——而且最大的那一项恰好等于 1，
分母至少是 1，除法也安全。

**这个结论什么时候不成立**：FP16 的范围小得多（最大 65504，`ln` 约 11），
所以 FP16 推理里 softmax 几乎总是要在 FP32 里算。这是 Phase 09 会遇到的真实约束。

**写下来**：假设 → 四个阈值的实测值 → 与理论值 88.7 对比 → FP16 下会怎样。
